# Phase 1b Hand-off: finish single-sourcing (delete the frozen `metal_rt_*` constants)

All paths relative to `zig/pkg/inference/`. Branch: `codex/quant-kernel-metal-compiler`.

## What is already done (Phase 1a — committed `fb8a25136`)

The **runtime region** (the kernels that compile into `src/backends/metal_kernels.m` and actually run in the model) is now generated by the descriptor-driven renderer, not from frozen bodies:
- `quant_kernel_metal_renderer.zig` gained `renderRuntimeRegion(allocator, kernels: []const RegionKernel)` — globally dedups the shared `antfly_qk_*` vocabulary + per-format dequant fragments, then renders every kernel body.
- `quant_kernel_compiler.zig::renderMetalRuntimeQuantRegion` was rewired to build the route list from `metal_production_schedules` (via `metalRuntimeKernelId(format, epilogue)` + `metal_renderer.decoderFor(format)`) and call `renderRuntimeRegion`.
- Validated on-device: `quant-kernel-metal-production-regression-check` **22/22** (max_abs_error ~1e-7, speedups retained), conformance ok, quant-kernel tests **107/107**.

**The gap this task closes:** the checked-in `.metal` artifact files (`src/ops/metal/generated/quant_kernel_*.metal`) still source from the **55 frozen `metal_rt_body_*` / `metal_rt_helper_*` string constants** (via `metalSmallBatchFileSource` → `first_general_metal_*_source` → `generatedSourceForArtifact`). So re-tuning a schedule updates the shipped region but leaves the `.metal` files (and thus the conformance harness) on stale v1 text. Deleting the frozen constants + rendering the `.metal` files from the same renderer makes the compiler *truly* single-sourced.

## The crux (why this is non-trivial)

`.metal` source text is consumed **for source-fingerprinting** by `artifactSourceFingerprint(artifact)` (`quant_kernel_compiler.zig:5507`), which `std.hash.Wyhash.hash`es the source returned by `generatedSourceForArtifact`. That fingerprint is woven into:
- Manifest JSON (`:5100`, `:5243` — `generated_source_fingerprint`).
- Promotion checks (`:6176` missing-source-fingerprint blocker; `:6407` evidence match).
- The checked-in `first_metal_runtime_evidence` records carry literal `.source_fingerprint = <u64>` values, asserted equal to `artifactSourceFingerprint` by tests at `:7749`, `:8724`, `:8750`.

So **changing the `.metal` source text (frozen v1 → rendered v2) changes every Metal source fingerprint**, and the checked-in evidence/manifest fingerprints must be regenerated to match. `artifactSourceFingerprint` currently carries `@setEvalBranchQuota(24_000_000)` because the frozen source is comptime-available; its callers are actually **runtime** (manifest builders take an allocator; evidence asserts are in tests), so moving to runtime rendering is viable.

## Recommended approach — render `.metal` at codegen runtime, regenerate fingerprints

Keep it Metal-small-batch-only; CUDA untouched.

### Step 1 — Add a runtime `.metal` renderer
Add to `quant_kernel_compiler.zig`:
```
pub fn renderMetalArtifactSource(allocator, artifact: GeneratedArtifact) ![]u8
```
It emits: license header + the `MetalSmallBatchHeader`-style comment block (kernel_id from `artifact.kernel_id`; `plan_id` = `metal/<fmt>/<row_bucket>/<epilogue>/small_batch`; `production_enabled` from `artifact.production_enabled`; a standard promotion comment) + `#include <metal_stdlib>\nusing namespace metal;\n\n` + `metal_renderer.renderKernel(allocator, artifact.kernel_id, decoderFor(artifact.format), metalRouteScheduleFor(...), artifact.epilogue)`. This reproduces `metalSmallBatchFileSource`'s wrapper, but the helpers+body come from the renderer. Verify the exact header bytes match the current `metalSmallBatchFileSource` output format (license text, comment lines, blank-line placement) so only the *kernel text* changes, not the framing.

### Step 2 — Make source + fingerprint runtime
Convert the source path from comptime-borrowed to runtime-rendered for Metal:
- Change `generatedSourceForArtifact` for the **Metal small-batch** artifacts to render via `renderMetalArtifactSource` (needs an allocator → give it an allocator param, e.g. add `generatedSourceForArtifactAlloc(allocator, artifact)`; keep the CUDA branches returning their comptime `[]const u8`). Update the ~4 callers (`:5509` fingerprint, `:6475` compile, `:6505` match) to thread the allocator. For CUDA, no allocation.
- `artifactSourceFingerprint` (`:5507`): hash the rendered Metal source (runtime). Drop `@setEvalBranchQuota` if no comptime caller remains (confirm by building). Its ~15 callers are runtime (manifest builders + tests) — thread the allocator.
- `emitCompiledSource` (`:6569`): for Metal, return `renderMetalArtifactSource(...)`; for CUDA, return `compiled.source` verbatim.
- `compiledSourceMatchesRoute` (`:6505`): compare against the rendered Metal source (or drop the source-equality check for Metal and keep the header/route checks).

### Step 3 — Delete the frozen surface
Once nothing references them:
- Delete all 55 `metal_rt_body_*` / `metal_rt_helper_*` constants (`:3821–4090`).
- Delete `metal_runtime_quant_sections` (`:4100`), `MetalRuntimeQuantSection`, `metalRuntimeQuantSectionFor` (`:4209`).
- Delete `metalSmallBatchFileSource` (`:4283`), `MetalSmallBatchHeader` (`:4271`) if unused, and the 25 `first_general_metal_*_source` / `first_lazy_metal_source` comptime constants.
- Keep every `first_general_metal_*_kernel_id`, `*_source_path`, `*_check_command` constant (they're metadata, unchanged) and the CUDA `first_*_cuda_*` sources.

### Step 4 — Update the two tests
- `:9188` — replace the "ends with frozen section" assertion with: re-render the region for this kernel and assert the `.metal` body matches the region body for that kernel (or assert the `.metal` file contains `kernel void <kernel_id>` and compiles). The intent is `.metal` body == shipped region body; source both from the renderer.
- `:10199` — replace `metalV1SectionNameForTest`/frozen-grep with: render each route and assert the schedule markers (`group_pos.x << 1` for cols==2; `simd_sum`/`partial[`/`simdgroup_id` per reduction). This is the same intent, rendered instead of grepped.

2. The checked-in `first_metal_runtime_evidence` `.source_fingerprint` literals (`:1765+`) and any manifest golden fingerprints in tests now differ. Regenerate them: build a tiny throwaway that prints `artifactSourceFingerprint(artifact)` per Metal artifact, or run the failing fingerprint tests and paste the "expected" values. Update the literals.
3. `zig build quant-kernel-codegen -- --check` must pass (byte-sync).
4. On-device: `zig build quant-kernel-metal-production-regression-check` **must stay 22/22** (the shipped region is unchanged from 1a — this is a sanity check that nothing regressed), and `quant-kernel-metal-runtime-check` conformance ok. Note: the `.metal` files feed the conformance harness (xcrun compile + numeric check) — they now compile v2, which must pass CPU-reference conformance (max_abs_error within tol).

## Alternative approach (lower blast radius, more renderer work)
Make `renderKernel` **comptime-capable** (build the string via `std.fmt.comptimePrint` / `++` instead of a runtime `ArrayListUnmanaged`+allocator), then define the `.metal` source constants as `const first_general_metal_q4_0_source = renderMetalFileComptime(...)`. This keeps the entire comptime fingerprint/manifest/evidence machinery untouched (fingerprints still comptime-derived; no allocator threading; no evidence-literal regeneration beyond the text change). Cost: a dual-mode or comptime renderer. Prefer this if you want to avoid touching the ~15 fingerprint call sites; prefer the runtime approach if you want to move toward "evidence as regenerated data" (more industry-grade).

## Risks
1. **Fingerprint churn (SEV-HIGH-tedium):** every Metal source fingerprint changes; multiple checked-in evidence literals + manifest golden-string tests must be regenerated. Miss one → a fingerprint-equality test fails. Regenerate systematically (Step 5.2).
2. **Header byte-exactness (SEV-MED):** the `.metal` file framing (license header, comment block, includes, blank lines) must match the current `metalSmallBatchFileSource` output so the diff is *only* the kernel text; otherwise `--check` churns and header-match checks (`compiledSourceHeaderMatchesSource`) may break.
3. **CUDA cross-contamination (SEV-MED):** `generatedSourceForArtifact` and `emitCompiledSource` also serve CUDA. Keep CUDA on the comptime/borrowed path; only branch Metal small-batch to rendering.
4. **`.metal` v2 numerics (SEV-LOW):** v2 is normalized v1 (same math); conformance must confirm max_abs_error within tol. The shipped region is already v2 and passed 22/22, so this is expected to pass.
