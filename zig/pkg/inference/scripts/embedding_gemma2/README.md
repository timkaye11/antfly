# EmbeddingGemma 2 qualification

This directory qualifies the pinned official BF16 checkpoint across text,
image, audio, and ordered mixed inputs. Video and quantized tiers are outside
the first production lane.

The checkpoint lives outside the repository. Its required pin is
`google/embeddinggemma-2@914f7f89142e33e77833254d9c9b90c3cef7303b`; the oracle refuses weights
whose 1,488,915,288 bytes do not hash to
`197a32965d4b1105faf060417baa899e193fb73cd401f42ec9295234d5553d79`.
The durable managed bundle used by the native runtime is
`.models/google/embeddinggemma-2--antfly-b093c73188527d2b`. It is installed
through the registry as
`google/embeddinggemma-2:bf16-safetensors-bundle-v1`.

```sh
zig/pkg/inference/zig-out/bin/antfly-inference pull \
  google/embeddinggemma-2:bf16-safetensors-bundle-v1 --models-dir .models
```

The qualified Python environment uses Torch `2.14.0+cu130` from the CUDA 13.0
wheel index; install that CUDA wheel explicitly before `requirements.txt` so a
generic CPU wheel cannot satisfy the reference dependency. The remaining pins
are NumPy `2.4.6`, SciPy `1.17.1`, Pillow `12.3.0`, tokenizers `0.23.2`,
torchvision `0.29.1`, sentence-transformers `6.1.0`, and the exact Transformers
source revision recorded in `requirements.txt`.

```sh
python3 -m venv /opt/antfly/embeddinggemma2-reference
REF_PY=/opt/antfly/embeddinggemma2-reference/bin/python
$REF_PY -m pip install \
  --index-url https://download.pytorch.org/whl/cu130 \
  'torch==2.14.0+cu130'
$REF_PY -m pip install \
  -r zig/pkg/inference/scripts/embedding_gemma2/requirements.txt
```

The explicit `torch==2.14.0` constraint in `requirements.txt` accepts the
installed `+cu130` local build and prevents torchvision or another transitive
dependency from replacing it. Generate the pinned oracle with that environment:

```sh
$REF_PY oracle.py \
  --model /tmp/antfly-embeddinggemma2/model \
  --device cuda --precision bf16 --output /tmp/embeddinggemma2-bf16.json

python qualify_endpoint.py --oracle /tmp/embeddinggemma2-bf16.json \
  --url http://127.0.0.1:8080/ai/v1/embeddings \
  --report /tmp/embeddinggemma2-qualification.json
```

Production CUDA serving must set both backend policy variables. An explicit
CUDA preload by itself does not change the backend used to resolve subsequent
API requests.

The L4 qualification binary is a stripped ReleaseFast CUDA build with the
SM89 artifact bundle:

```sh
cd zig/pkg/inference
zig build -Doptimize=ReleaseFast -Dstrip=true -Dcuda=true \
  -Dcuda-artifacts=sm89
```

Use `-Dcuda-artifacts=fatbin` for the distributable bundle covering its listed
architectures. This BF16 CUDA profile requires SM80 or newer hardware. The
`portable` compute-75 artifact contains PTX ISA 9.2 generated by CUDA 13.2; it
requires a driver capable of JIT-compiling that toolchain output. Driver
580.159.03 reports CUDA 13.0 and rejects this PTX, so the L4 qualification uses
the bundled SM89 SASS. On a compatible newer driver, the portable artifact can
JIT its guarded fallback on SM80+ devices, but it does not qualify physical
SM75/Turing hardware or its performance. The host dispatch guard prevents
selecting unavailable WMMA implementations; it does not replace the driver's
PTX-version check.

```sh
ANTFLY_INFERENCE_PREFERRED_BACKEND=cuda \
ANTFLY_INFERENCE_REQUIRED_BACKEND=cuda \
zig/pkg/inference/zig-out/bin/antfly-inference run \
  --models-dir .models \
  --preload-model embedder:cuda:google/embeddinggemma-2:bf16-safetensors-bundle-v1 \
  --host 127.0.0.1 --port 18090 \
  --host-budget-mb 8192 --backend-budget-mb 12000 \
  --combined-budget-mb 22000 --scratch-budget-mb 8192
```

Those are the explicit L4 qualification budgets. The 8 GiB scratch allowance
is needed for the standalone B8/B32, maximum-8192-token capacity smoke; a
server using its host-RAM-derived default may correctly reject that boundary
case. The seven timed representative cells use the same resident server, but
the large-batch smoke is a finite/output/usage/batch-consistency capacity
check rather than a latency claim. The published report records the actual
22,000 MiB ceiling used to avoid conflating admission policy with device
execution; a separate 16 GiB combined-budget probe must pass before claiming
that lower ceiling is sufficient.

Local ordered embedding accepts either repeated modality flags with
`--combined` or an API-shaped body with `--content-json`. MRL dimensions use
`--dimensions 128|256|512|768`:

```sh
zig/pkg/inference/zig-out/bin/antfly-inference embed \
  .models/google/embeddinggemma-2--antfly-b093c73188527d2b \
  --backend cuda --content-json request.json \
  --dimensions 256
```

`qualify_endpoint.py` gates oracle cosine, norms, trained MRL dimensions,
truncate-and-renormalize consistency, batch/single agreement, and CUDA backend
provenance. `benchmark_paired.py` alternates Antfly and a PyTorch HTTP worker
for at least 100 measured iterations. Each workload passes only when the lower
95% confidence bound of the throughput ratio is at least 0.90 and the p95
latency ratio is at most 1.10.

Start the resident comparison worker with `pytorch_worker.py --model
/tmp/antfly-embeddinggemma2/model`, then pass its URL and the Antfly endpoint
to `benchmark_paired.py`. Both endpoints accept the same ordered text, image,
audio, and mixed content groups. Select an official media fixture with
`--case image|audio|mixed_ordered`; `--case text` uses the corpus arguments.

The reference worker exposes `--attention eager|sdpa|flex_attention` and
`--compile none|default|max-autotune`. It reports the effective attention,
precision, Torch/Transformers/Python/CUDA/cuDNN/driver versions, and GPU model.
It refuses an attention implementation that the installed Transformers model
does not support. Select the fastest option only after checking it against the
pinned BF16 text oracle:

```sh
PYTHONPATH=/tmp/antfly-embeddinggemma2/python-overlay \
  /tmp/antfly-gliner25-family/venv/bin/python select_pytorch_baseline.py \
  --model /tmp/antfly-embeddinggemma2/model \
  --oracle /tmp/antfly-embeddinggemma2/oracle-bf16.json \
  --candidate-url http://127.0.0.1:18090/ai/v1/embeddings \
  --candidate-model embeddinggemma-2 \
  --iterations 10 --report /tmp/embeddinggemma2-pytorch-selection.json
```

The selector evaluates every supported attention/compile pair and requires a
minimum cosine of 0.999 across all text oracle cases and the exact native
candidate cell before considering its latency. `--candidate-url` and
`--candidate-model` make that CUDA provenance check mandatory. Worker and
paired benchmark warmups are reported explicitly.

## Current qualification status (2026-10-08, NVIDIA L4)

The final tested binary is the stripped ReleaseFast SM89 build with SHA-256
`bda59bbadd9fdc2d1af83abb2312d751eb8df780a54140bc75b676d76f1f73b9`.
The compact evidence index is
[`results/l4-2026-10-08.json`](results/l4-2026-10-08.json); its immutable
as-built source manifest covers 123 files, including 39 runtime and build files:
[`results/l4-2026-10-08-source-manifest.json`](results/l4-2026-10-08-source-manifest.json).
Raw paired samples are retained under
[`results/l4-2026-10-08-raw/`](results/l4-2026-10-08-raw/).

The exact final binary passes 60/60 local CLI gates and 71/71 HTTP gates for
text, image, lossless 16 kHz audio, ordered mixed input, all trained MRL
dimensions, exact token usage, batch/single agreement, and CUDA provenance.
The minimum final official-fixture cosine is `0.99985206447` for audio.

Against the fastest parity-valid compiled-default PyTorch SDPA reference, six
of seven 100-pair cells pass both production performance gates (throughput

1.10):

Image misses only the throughput-confidence gate; its p95 ratio is `1.08499`
and its cosine is `0.99996415`. Results are reported as measured without
selective reruns.

The extended nine-case audio matrix does not pass the 0.999 cosine gate. Its
minimum is `0.9989237258` for one second of mono 44.1 kHz audio. A diagnostic
that forces all audio operations to the host passes at `0.9991064044`, which
localizes most of this gap to the device audio hooks, but that diagnostic is
not the default production path. The official 16 kHz audio fixture remains
competitive and passes at cosine `0.99985951`.

The immediately preceding binary, SHA
`4aa4dda5e08ca2ecd7bbb72dfb7e5663a9d4c76714e1fe2695ea65ca46a60076`,
passes the 14/14 rejection/cancellation/session contract suite, 26/26
concurrency and per-item-failure suite, B8/B32 heterogeneous 8192-token
capacity smoke, 20/20 extended multimodal matrix, and cuDNN-present, absent,
and explicitly-disabled fallback checks. The final source manifest changes
only the bit-exact sparse mel helper and its projector call site, so the index
retains these checks as unchanged-path regression evidence rather than
claiming they were rerun on the final SHA. The sparse helper's tracked proof
checks all 12,672 outputs bit-for-bit and measures roughly 4.16 ms saved for
the 99-frame fixture.

This is a draft-support result because the 44.1 kHz audio quality gate and the
image throughput-confidence gate remain open. Forty-one of the 45 broader
text matrix cells and secondary GPU architectures are unmeasured. Video and
quantized tiers remain outside this release.
