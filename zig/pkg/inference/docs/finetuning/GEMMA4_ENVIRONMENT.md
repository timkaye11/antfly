# Gemma training environment controls

Prefer typed recipe options. These controls support rollback and numerical
qualification; enabling an experimental route does not qualify it for release.
Unset controls use source-defined defaults, including model-shape-dependent
admission. `ENABLE` requests a route and `DISABLE` rolls it back; when both are
present the corresponding resolver determines precedence. Presence controls
must be removed to restore defaults; assigning zero does not unset them.

The [shared policy](../../src/finetune/gemma4_preference_environment.policy)
is authoritative for preference admission and qualification sanitization.
Unknown in-scope overrides and noncanonical values fail admission on both
native and Metal. SFT captures in-scope overrides, including diagnostics, in
its run identity. Changing a captured value or its presence prevents resume.
The policy source itself participates in the digest. Process environment must
remain fixed for a training run; low-level kernels still read some controls
at dispatch time. Moving every resolver out of hot paths remains open.

`TERMITE_METAL_REQUIRE_LINEAR_CCE=1` on the direct SFT command rejects
full-logits fallback when the bounded BF16 cut-cross-entropy route is unavailable.
It is not an admitted preference override; use the table below for preference
runs. GRPO uses temperature-scaled, full-vocabulary policy scores for its
likelihoods and gradients. Top-k/top-p remain rollout filters; see the
[scoring contract](GEMMA4.md#grpo-scoring-policy).
